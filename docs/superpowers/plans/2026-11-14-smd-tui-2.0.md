# SMD-TUI 2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build SMD-TUI 2.0, a modular, lightweight, strictly read-only interactive Linux hardware intelligence and terminal monitoring application in Bash 5.x.

**Architecture:** A clean 3-tier modular architecture separating hardware metric collection (`collectors/`), mathematical calculations, history ring buffers and alert evaluation (`core/`), and ANSI terminal UI rendering and input handling (`ui/`). Managed by an application controller (`app.sh`), a safe configuration loader (`config/`), and validated by an automated test suite (`tests/`).

**Tech Stack:** Bash 5.x, Linux sysfs (`/sys`), procfs (`/proc`), `tput`, ANSI escape codes, coreutils, util-linux, procps, iproute2, Bats-core / ShellCheck test suites.

**Spec:** Local Master Development Prompt (`SMD-TUI 2.0: Linux Hardware Intelligence & Interactive Terminal Monitor`)

## Global Constraints

- Primary language: Bash 5.x.
- Platform: Linux distributions (Ubuntu, Debian, Fedora, Arch, RHEL, WSL2, etc.).
- Strict Read-Only Policy: Zero hardware control, zero writes to `/proc` or `/sys`, zero process kills, zero service modifications, zero disk mount/partition modifications, zero sudo/root privilege requirements.
- Allowed writes: ONLY application-owned configuration, history, log files, and user-requested CSV/text exports under XDG standard directories (`$XDG_CONFIG_HOME`, `$XDG_DATA_HOME`, `$XDG_STATE_HOME`).
- No external heavy dependencies; no desktop GUI; no web servers.
- Clean terminal restoration on normal exit, SIGINT, SIGTERM, and SIGHUP (`tput rmcup`, `tput cnorm`, stty reset).

## Review Focus

1. **Virtual/Container/Restricted Environments (e.g. WSL, Docker, Cloud VMs without hardware sensors):**
   Thermal, fan, and battery collectors must detect missing `/sys` directories and return clean `N/A` statuses without crashing, erroring, or printing garbage.
2. **Bash Fixed-Point and Integer Division:**
   Bash only supports integer arithmetic; all percentage and rate calculations must avoid divide-by-zero errors when total capacity, delta time, or memory totals are 0 or empty.
3. **Safe Configuration Parsing:**
   The config loader must NEVER use `source` or `eval` on user config files; it must safely parse key=value lines and strictly reject invalid characters, command injections, or out-of-range thresholds.
4. **Terminal Resizing and Screen Buffer Integrity:**
   Dynamic terminal resizing (`SIGWINCH`) must redraw properly without cursor drift, screen tearing, or buffer overflows across 80x24 minimum to 200+ column displays.
5. **Non-blocking Input and Responsiveness:**
   The main event loop must remain responsive to keyboard navigation (`1-9`, arrows, `q`, `r`, `p`, `e`, `h`) while adhering to the configured refresh interval without spawning excessive subprocesses.
